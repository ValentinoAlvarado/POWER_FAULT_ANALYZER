# PFA-WORKBENCH-004.2 — Transactional Interactive Property Editor

## Scope

This increment adds an editable selection inspector to the existing Qt Workbench. All commits are routed through `NetworkWorkspaceCommands.execute_many`; the inspector does not mutate domain objects directly.

## Editable selection types

| Selection | Editable fields | Semantics |
|---|---|---|
| AC bus / connection node | Name, nominal L-L voltage, X/Y position, diagram rotation | Name and voltage update the domain bus through `UpdateBus`; geometry is presentation-only. Voltage compatibility remains enforced by the Network aggregate. |
| Canonical equipment | Display label, X/Y position | Label is a `DiagramLabelPlacement` override; it does not rename or alter electrical equipment data. Associated labels follow equipment movement while retaining their relative offset. |
| Drawing-only source symbol | Drawing label, X/Y position, rotation | Remains a drawing-only asset; no electrical topology is inferred. |
| Independent annotation | Text, X/Y anchor, text rotation | Stored as presentation metadata and independent from the electrical model. |

Equipment rotation is intentionally not offered for canonical two-terminal equipment in this increment; those orientations are derived from the topology and bay layout. A future editor command must define a supported route/terminal behavior before exposing arbitrary equipment rotation.

## Transaction and undo model

- One Apply action becomes one `QUndoCommand`.
- Redo and undo submit the complete field set as one `NetworkWorkspaceCommands.execute_many` transaction.
- Before insertion into `QUndoStack`, the entire edit is replayed against an isolated deep copy of `NetworkWorkspace`. Domain failures therefore reject the edit before the UI undo history or live aggregate changes.
- Bus name/voltage, presentation position and bus rotation are grouped atomically.
- The inspector tracks whether position and rotation were explicit or generated by automatic layout. Undo removes newly-created explicit metadata and restores automatic placement rather than leaving hidden coordinate overrides behind.
- Equipment display-label edits use a stable deterministic generated-label UUID. The first edit adds an override; undo removes it and reveals the generated default; redo reinstates it. The same label follows its owning equipment when its position changes.
- `RemoveDiagramLabel`, `RemoveDiagramPosition` and `RemoveDiagramRotation` commands remove presentation overrides through the same command bus.
- `NetworkWorkspace` and `Network` identities remain managed by the established 004.1 transaction boundary.

## Persistence and topology boundary

Diagram label overrides, positions, rotations and drawing-symbol placements are stored by the existing JSON network-document repository. Presentation edits do not create or remove terminal-to-bus connections. Bus voltage edits pass through the domain aggregate's connection voltage-compatibility checks; invalid voltage changes are rejected by preflight without changing the live Workspace, command revision or `QUndoStack`.

## Verification

- Unit/integration tests cover label override removal, position/rotation metadata removal, rollback behavior, bus kind preservation and JSON round-trip.
- `scripts/verify_pfa_workbench_004_2_property_editor.py` runs the real Qt Workbench offscreen on Windows: connected-bus voltage preflight rejection; bus name/voltage/position/rotation editing; restoration of implicit layout state; undo/redo; equipment display-label override and owner-following movement; and preservation of electrical connections/equipment identity.
- Full installer verification also reruns PFA-DESIGN-003.6 route parity and the 004.1 command architecture verifier.

## Deliberate limitations

This increment does not yet claim complete editing of every equipment electrical parameter, project-level multi-selection, a unified command journal across all legacy dialogs, or a fully transactional project-file save pipeline. Those remain separate acceptance targets.
