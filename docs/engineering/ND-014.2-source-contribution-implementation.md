# ND-014.2 — Source Contribution Analysis

## Purpose

This increment adds source inventory and source-resolved fault-current attribution to the existing sequence-network model. It uses the physical models already stamped by `SequenceNetworkBuilder`; it does not replace the academic short-circuit solver or claim to implement every source-specific IEC 60909 procedure.

## Implemented components

- `standards/iec60909/source_inventory.py` builds a deterministic inventory from non-passive Thevenin shunts and registered converter current sources.
- `infrastructure/numerical/iec60909_source_contributions.py` solves source-only prefault voltage contributions on the common sequence-network admittance matrices, applies the existing fault-boundary solver to each contribution, and returns sequence- and phase-current phasors at the faulted bus.
- `IEC60909StudyScenario.required_sequences` defines the sequence networks required by the fault connection. A source may contribute fault-induced current in a sequence where it has no independent internal source voltage; therefore contribution sequence keys are checked against the fault connection, not against the source's independently energized sequences.
- `IEC60909CurrentCalculationRequest` validates source identity, name, family, mode and model reference against its scenario descriptor.
- `IEC60909Calculator` accepts multiple `ExternalGrid` network-feeder equivalents for the initial symmetrical current where every feeder is present in each sequence network required by that fault.

## Contribution method

The source-contribution analyzer uses linear superposition on the supplied sequence-network model:

1. It assembles the required sequence Ybus matrices and factorizes each matrix once for the analysis.
2. For each voltage-source model, it solves the common Ybus system using only that source's stamped Norton current-injection vector.
3. For each converter, it solves the common Ybus system using the explicit, engineer/vendor-supplied sequence-current command for that converter alone.
4. It passes each source-only prefault sequence-voltage contribution to the existing `ShortCircuitSolver` while retaining the common network driving-point impedances and fault connection.
5. It converts the resulting sequence and phase currents to kA and checks that all source contributions reconstruct the total sequence and phase current within configured absolute/relative tolerances.
6. It records the source family, representation mode, model reference and assumptions in `IEC60909CalculationTrace`.

The decomposition is a model-based attribution of the existing linear sequence-network solution. It is not, by itself, the normative IEC correction of a synchronous or asynchronous machine contribution.

## Explicit scope limits

- Synchronous and asynchronous machine contributions use the supplied physical sequence/Thevenin models. Machine-specific IEC source correction factors have **not** been applied by this analyzer.
- The current asynchronous equipment model is `InductionGenerator`. This increment does not add a separate induction-motor equipment model.
- Converter contributions require fixed sequence-current phasors supplied through `ConverterSequenceCurrentCommand`. They are not a dynamic converter-control, PLL, current-priority, voltage-dependent limiter or grid-forming response model.
- The existing IEC calculator's multiple-network-feeder extension reports only the initial symmetrical current. For multiple external feeders, peak, breaking, steady-state and thermal quantities remain unavailable and are accompanied by diagnostics.
- Multiple external feeder IDs must be represented in all sequence networks required by an unbalanced fault. Missing feeder sequence models are rejected.
- The IEC calculator continues to reject synchronous/asynchronous machine and converter source correction cases until their edition-specific procedures are verified and implemented.
- Interior-line faults are not converted into IEC 60909 studies by this increment.

## Regression coverage

Tests cover source inventory classification, source attribution for all four fault connections, reconstruction residuals in sequence and phase domains, remote rotating machines connected through a line, fixed-phasor converter attribution, invalid source descriptors, source metadata integrity, and multi-feeder sequence consistency.
