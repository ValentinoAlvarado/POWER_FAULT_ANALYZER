# ND-014.3 — Current-source equipment and three-winding transformer data

**Status:** Implemented data contracts and physical model integration; normative calculation policies remain gated.
**Target edition:** IEC 60909-0:2026, Edition 3.0.

## Implemented

- Added `IEC60909CurrentSourceInput` for explicitly supplied positive-, negative- and zero-sequence current phasors in kA. The input requires source family, rated voltage, source-data reference, method reference and standard edition. All three sequences must be declared; a missing value is not silently treated as zero.
- Added `validate_iec60909_current_source_input` to validate the source ID, service state, current-source mode, source family, standard edition and fault-required sequence set against a normalized study scenario.
- Kept this standard-specific current-source contract separate from `ConverterSequenceCurrentCommand`, which remains the fixed-phasor academic/engineering input path. No automatic conversion exists between them.
- Added the `InductionMotor` physical equipment entity and explicit `InductionMotorParameters`. It contributes to positive/negative/zero sequence networks only according to supplied impedances, stator connection and neutral grounding. Only the initial equivalent is supported.
- Integrated induction motors into `SequenceNetworkBuilder` as asynchronous-machine Thevenin sources and exported `IEC60909InductionMotorInput` as an immutable, traceable snapshot of the supported initial-equivalent inputs.
- Added `IEC60909ThreeWindingTransformerCorrectionInput` and a readiness assessment. Readiness requires pairwise impedance test provenance, all winding nameplate ratings and the explicit three-port zero-sequence model/reference. No zero-sequence path is inferred.

## Explicitly not implemented

- No converter or power-station-unit current-source phasor is derived from nameplate/control data in this increment. The supplied kA phasors must already have been obtained under a reviewed IEC procedure or validated model.
- No three-winding transformer correction coefficient is calculated yet. The readiness object only validates and snapshots inputs for a future clause-mapped policy.
- No induction-motor breaking-current, steady-state-current or time-domain decay method is implemented.
- The existing IEC calculator continues to reject current-source and three-winding transformer cases until the relevant calculation policies are implemented and verified.

## Normative boundary

The public contents of IEC 60909-0:2026 identify current-source installations in 5.2.3, three-winding transformers and their correction factors in 6.3.2–6.3.3, asynchronous motors in 6.9.3, and converter/power-station-unit models in 6.10–6.11. The software contracts follow this equipment taxonomy. Exact coefficients, equations, limits and applicability rules must be checked against the licensed final text before a numerical policy is implemented.

## Acceptance evidence

The tests cover explicit sequence completeness, family/mode/source identity matching, current-base conversion, induction-motor base/grounding behavior, sequence-network integration, motor data snapshots, three-winding input readiness and rejection of absent zero-sequence test models. Software regression does not constitute independent engineering validation or IEC conformity.
