# PFA Code & Automation Studio — source audit

**Audit basis:** uploaded `POWER_FAULT_ANALYZER_SOURCE(3).zip`, not a live Windows checkout.

## Verified implementation

- `CodeAutomationStudio` is a Qt widget with a `QPlainTextEdit`, Validate Script and Build Diagram actions, plus a text output pane.
- The editor seeds a `ScriptProject` example and passes a resulting `NetworkWorkspace` to the existing Network Design canvas.
- `ScriptProject` constructs real `Network`, `Bus`, `Terminal` and `EquivalentSource` domain objects and explicit terminal-to-bus connections.
- The authoring API stores drawing coordinates in `NetworkWorkspace.diagram_positions`, separate from the electrical aggregate.
- `assert_valid()` delegates to the domain structural validator or calculation validator according to the selected flag.

## Confirmed scope boundaries

- `ScriptProject` currently exposes `add_bus` and `add_equivalent_source`; it is not a complete typed API for lines, transformers, generators, loads, switches, protection, studies, results, sheets or annotations.
- The embedded editor is `QPlainTextEdit`; syntax highlighting, LSP, completion, go-to-definition, refactoring, module/project tree, variable explorer and execution history are not implemented.
- `_execute()` calls Python `exec(compile(...))` inside the Workbench process with the current user's permissions. This can execute arbitrary Python and can block or crash the GUI. The warning is accurate; this is not a sandbox.
- Validation currently executes the script to inspect its resulting `ScriptProject`. It is not static analysis and must not be used on untrusted code.
- Build Diagram sends the returned in-memory `NetworkWorkspace` to the canvas. This is a real shared domain/workspace path, but not a transactional three-document synchronization protocol with a declarative source document.
- No isolated worker protocol, allow-listed capability broker, timeout/cancellation, structured IPC, or process lifecycle manager exists for scripts.

## Engineering decision

Do not bolt syntax-highlighted widgets onto the existing in-process `exec()` and call the result a secure automation studio. The next safe implementation boundary is a declarative, versioned model specification (JSON/Pydantic contract) generated by the Python authoring API in a separate worker process, validated in the host, then applied as one transaction to the canonical domain aggregate. The host should render the resulting `NetworkWorkspace`; it must not accept pickled Python objects or execute script text inside Qt.

A separate editor upgrade can then adopt a maintained Qt code-editor component and an LSP client after dependency, license, maintenance and PySide6 compatibility review. No editor/LSP dependency was added in this increment.
